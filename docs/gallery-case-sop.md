# Gallery 新增案例 SOP

下一次新增案例時，使用者只需要先把原圖放進 `public/images/gallery/`，再提供一個「案例識別」。單一案例通常可在 10–20 分鐘內完成資料與網站更新；圖片較多或資料需釐清時另計。

## 目的與完成標準

這份 SOP 用於同步完成三件事：

1. 完善 `outputs/gallery-case-mapping/BeerTaps-Gallery-案例對照表.xlsx` 的「案例對照表」與「圖片清單」。
2. 將案例、圖片、Caption、Alt 與精選設定更新到網站。
3. 商品類別為「酒吧」或「餐酒館」時，同步更新知識專欄〈全台各地特色酒吧、餐酒館〉。

完成時必須符合以下條件：Excel、原圖、縮圖與網站的案例識別、圖片數量、檔名、主圖、Caption、Alt 完全一致；本機檢查通過；內容留給使用者審閱，不自行發布。

## 固定資料規則

### 案例識別與圖片命名

| 前綴 | 設備形式 | 新圖片命名範例 |
| --- | --- | --- |
| `s-` | 小型啤酒機 | `s-example-1.jpg` |
| `l-` | 大型出酒系統 | `l-example-1.jpg` |
| `w-` | 壁出式啤酒牆 | `w-example-1.jpg` |
| `c-` | 客製化設備 | `c-example-1.jpg` |

- 新案例的檔名使用小寫案例識別、半形連字號與連續圖片號碼，從 `1` 開始，不缺號、不重複。
- 尋找圖片時只接受「完整案例識別＋圖片號碼」的精確符合，避免把相近案例混在一起。
- 舊案 `w-1913.jpg` 是沒有 `-1` 的歷史例外；新案例不再沿用此格式。
- 前綴與設備形式不一致、圖片號碼不連續或檔名重複時，先停止建檔並向使用者確認。

### Excel 排序

「案例對照表」的設備形式固定依下列順序分組：

1. 小型啤酒機
2. 大型出酒系統
3. 壁出式啤酒牆
4. 客製化設備

新增案例必須插入對應設備形式的區塊，不能加在整張表最後。相同設備形式內依「案例識別」由 A 到 Z 排列；除非使用者另外指定展示順序。

「圖片清單」使用相同設備形式順序，再依案例識別與圖片號碼遞增排列。同一案例的圖片必須保持連續。

## 執行流程

### 1. 使用者放圖並提供案例識別

使用者將原圖放到：

```text
beertaps_website_new/public/images/gallery/
```

接著只需回覆案例識別，例如：

```text
l-example
```

### 2. 助理先完成圖片盤點與案例基本列

助理依案例識別完成下列動作：

1. 在 `gallery` 找出所有精確符合的圖片，依圖片號碼排序。
2. 由案例識別前綴確認「設備形式」，不得只靠畫面猜測。
3. 計算圖片數量，整理完整圖片檔名清單。
4. 在 Excel「案例對照表」的正確類別位置插入新列。
5. 先填入「案例識別、設備形式、圖片數量、圖片檔名」。

盤點完成後，助理需回報找到的圖片數量與檔名；若找不到圖片、出現缺號或同名衝突，先停止並說明問題。

### 3. 請使用者補齊案例資料

助理提供以下固定格式，請使用者填寫；使用者通常可在 3–5 分鐘內完成：

```text
商鋪名稱：
地理位置：
商品類別：
主圖號碼：
首頁精選：是／否
龍頭數：
酒柱型式：
解決的操作問題：
備註：
```

填寫規則：

- 商品類別使用「酒吧、茶飲、啤酒車、餐廳、招待所、餐酒館」之一；新類別必須先確認。
- 主圖號碼必須存在於本案例圖片號碼中，而且只能有一張主圖。
- 首頁精選只接受「是／否」；網站會同步維護對應設備頁的 `featuredCaseIds`。
- 龍頭數填數字；無法確認時留空，不猜測。
- 酒柱型式、操作問題與備註只記錄已知事實；不確定的資訊留空並標示待確認。

### 4. 助理完成兩張工作表

收到使用者資料後，助理先補齊「案例對照表」剩餘欄位，再逐張檢視原圖並新增「圖片清單」資料。

| 工作表 | 助理必須完成的欄位 |
| --- | --- |
| 案例對照表 | 案例識別、設備形式、商鋪名稱、地理位置、商品類別、圖片數量、圖片檔名、主圖號碼、首頁精選、龍頭數、酒柱型式、解決的操作問題、備註 |
| 圖片清單 | 圖片檔名、案例識別、圖片號碼、設備形式、商鋪名稱、地理位置、商品類別、是否主圖、畫面中的設備、Caption、圖片 Alt |

逐圖欄位規則：

- 「是否主圖」只在主圖那一列填 `是`，其他圖片填 `否`。
- 「畫面中的設備」只描述照片中可確認的龍頭數、酒柱／設備形式、滴酒盤、餐車或其他可見設備；每張照片分別判斷。
- Caption 格式為 `商鋪名稱／地理位置｜具體設備與解決的操作問題。`，不得添加照片無法支持的效果或成果。
- 圖片 Alt 使用 `商鋪名稱＋地理位置＋商品類別／場域＋可見設備`，不得只寫「主視覺、另一角度、照片」。
- 同一案例不同圖片若看見的設備不同，Caption 與 Alt 必須各自描述；不能直接複製同一句。

Caption 與 Alt 應使用自然、可讀的繁體中文。若現場或設備資訊不足，先列出待確認項目，不以推測補滿文字。

### 5. 助理更新網站內容

助理依設備形式更新案例資料：

| 設備形式 | 案例資料檔 |
| --- | --- |
| 小型啤酒機 | `data/equipment/small-cases.ts` |
| 大型出酒系統 | `data/equipment/large.ts` |
| 壁出式啤酒牆 | `data/equipment/wall.ts` |
| 客製化設備 | `data/equipment/custom.ts` |

同時完成以下連動：

1. 將使用者指定的主圖放在該案例 `images` 陣列第一個位置；檔名不必重新編號。
2. 更新 `data/equipment/case-image-alts.ts`；每張圖描述不同時，加入圖片檔名層級的 override。
3. 小型啤酒機的 Caption 直接維護在 `small-cases.ts`；其他三類維護於 `data/equipment/case-captions.ts`。
4. 首頁精選為「是」時，將網站案例 ID 加入該設備資料的 `featuredCaseIds`；小型啤酒機網站案例 ID 依現況移除 `s-` 前綴，其他三類保留完整案例識別。
5. 以原圖建立同檔名縮圖，放進 `public/images/gallery-thumbnails/`；縮圖寬度為 900 px、等比例縮放，格式與方向保持正確。

小型啤酒機還需要 `demand、setup、result`。助理以「解決的操作問題、龍頭數、酒柱型式、備註」整理這三段文字；資料不足時必須先請使用者補充，不能杜撰營運成果。

### 6. 酒吧／餐酒館的知識專欄連動

商品類別為「酒吧」或「餐酒館」時，助理同步更新：

```text
app/blog/[slug]/content.tsx
```

更新規則：

- 酒吧加入 `barRegions`；餐酒館加入 `bistroRegions`。
- 依地理位置插入正確地區，不加在整份名單最後；沒有對應地區時新增地區區塊。
- 同一商鋪已存在時不重複新增，改為核對名稱與地理位置。
- 同步更新文章上方的店家總數、酒吧數、餐酒館數；計數以不重複商鋪為準。
- 沒有指定 Google Maps 連結時沿用網站的名稱＋地點搜尋連結；不得猜測店家網址。

## 交付前檢查

### Excel 與圖片

1. 案例識別在「案例對照表」只出現一次，且位於正確設備區塊。
2. 圖片數量＝圖片檔名數＝「圖片清單」列數＝原圖數＝縮圖數。
3. 圖片號碼連續、無重複；主圖號碼存在，且只有一列「是否主圖＝是」。
4. 每張圖的商鋪、位置、類別、設備形式與案例列一致。
5. Caption、Alt 與畫面可見內容相符，沒有「主視覺／另一角度」等無資訊文字。

### 網站

1. 案例出現在正確設備頁，主圖、圖片順序與首頁精選設定正確。
2. 所有原圖與縮圖路徑有效，Lightbox 可開啟並顯示正確 Caption、Alt。
3. `case-image-alts.ts`、Caption 資料與 Excel 逐圖資料一致。
4. 酒吧／餐酒館案例已更新知識專欄，地區與三個統計數字正確。
5. TypeScript、ESLint、正式建置與圖片 Sitemap 檢查通過。

## 交付與發布邊界

助理完成後交付以下結果：找到的原圖與縮圖清單、Excel 新增列、網站異動檔案、檢查結果，以及需要使用者確認的 Caption。未取得明確指示前，不自行建立可索引的案例詳情頁、不提交、不推送，也不部署正式站。
